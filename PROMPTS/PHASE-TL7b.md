# Phase TL7b — Reverb & Delay Sends per Orbit

> **Spec status:** full.
> **Automation:** 🤖👂 auto + human check. Routing, send levels and tail/echo energy are
> tested automatically. Acceptance needs a human listen (reverb send, delay echoes,
> two orbits with different settings) recorded in the PR.

**Milestone:** 1 — Tidal-Lisp core
**Depends on:** TL7a (per-event output chain `with-inserts`, `trigger_v3` slot layout)
**Unblocks:** TL7c (`delay-sync`), SONG2 (automating `room`/`delay`), EXP1 (renders sends)

## Goal

Events can send part of their signal to a shared reverb and a shared delay, at a level
set per event, like SuperDirt/Strudel `room` and `delay`. The effects are grouped in
**orbits**. Each orbit owns one reverb and one delay, so a drum part and a pad can use
different reverb sizes. Send levels are patternable and accept signals. The dry signal
still goes through the track's `track-fx` chain as before.

```lisp
;; Before — reverb only per track (wet on the whole track) or global
(track :keys (->> (seq :c4 :e4 :g4) (synth :epiano) (fx :reverb 0.4)))

;; After — per-event sends, patternable
(->> (seq :c4 :e4 :g4 :b4) (synth :epiano) (room (seq 0 0.6)) (size 0.8))
(->> (seq :sd :_ :sd :_) (delay 0.4) (delay-time 0.375) (delay-feedback 0.5))
(stack (->> (seq :bd :sd) (room 0.2) (orbit 0))
       (->> (slow 2 (seq :c3 :g3)) (synth :saw) (room 0.7) (size 1) (orbit 1)))
```

## Design decisions

Decided with the project owner on 2026-11-10.

1. **The send effects exist once, as Web Audio nodes.** Each orbit has one
   `ConvolverNode` reverb and one feedback `DelayNode`, built from browser nodes for
   every context (live and offline). The WASM worklet does **not** get its own
   reverb/delay. Instead it exposes per-orbit **send outputs**, and those feed the same
   orbit nodes. So there is no second implementation of the send effects.
2. **4 orbits** (0–3), default 0. Out-of-range values are clamped and produce one
   warning per evaluation (`orbit 7 is out of range 0–3; using 3`).
3. **Orbits are independent of tracks.** The dry signal goes event → (inserts) → track
   chain → master. The send taps the event after inserts and pan, before the track
   chain, and the orbit returns go into `master-gain`, so the global `fx` chain still
   processes them. Muting a track stops its events (and therefore its sends). Tails
   already in the reverb ring out.
4. **Orbit settings come from events, last event wins** (SuperDirt behaviour): `size`,
   `delay-time` and `delay-feedback` on an event set that orbit's reverb/delay
   parameters at the event's time. Events without these keys leave the orbit's settings
   unchanged. `(stop)` resets every orbit to its defaults.
5. **Units:** `delay-time` in seconds (Strudel `delaytime`); a cycle-synced variant
   (`delay-sync`) is TL7c. `size` is 0–1, mapped to the reverb length (below). Check
   Strudel's `roomsize` scale in `docs/STRUDEL-PARITY.md` and the Strudel docs. If it
   differs, document the mapping in USAGE.md rather than changing this range.

## Parameters

| Function | Event key | Range (clamped) | Default | Meaning |
|---|---|---|---|---|
| `room` | `:room` | 0–1 | 0 | reverb send level |
| `size` | `:size` | 0–1 | 0.5 | orbit reverb length: `0.3 + 5.7·size` s |
| `delay` | `:delay` | 0–1 | 0 | delay send level |
| `delay-time` | `:delay-time` | 0.01–4 s | 0.25 | orbit delay time |
| `delay-feedback` | `:delay-feedback` | 0–0.95 | 0.5 | orbit delay feedback |
| `orbit` | `:orbit` | 0–3 (integer) | 0 | which orbit's effects to send into |

## Background

- TL7a's `with-inserts` (`app/src/repulse/audio.cljs`) is the single place where every
  JS voice's output is wired. `trigger_v3` in `packages/audio/src/lib.rs` carries
  fixed parameter slots 0–11. TL7b appends slots and never reorders them.
- `init-worklet!` (`audio.cljs` ≈ line 79) creates
  `new AudioWorkletNode(ac, "repulse-processor", {outputChannelCount: [2]})` (one stereo
  output) and connects it to `@master-gain`. `build-master-chain!` builds master-gain
  → tap → analyser → destination. The global `fx` chain is inserted by
  `app/src/repulse/fx.cljs`.
- `app/public/worklet.js` `process()` copies the interleaved buffer from
  `engine.process_block(n, currentTime)` into `outputs[0]`.
- `AudioEngine::process_block_raw` mixes all voices into one stereo buffer; the
  equal-power pan is computed per voice per sample.
- Existing plugins `app/public/plugins/reverb.js` (noise-burst impulse response, generated by
  `makeImpulseResponse(ctx, duration, decay)`) and `delay.js` (feedback DelayNode)
  show the node layouts to reuse. TL7b doesn't use the plugins themselves: orbits are
  not user-loadable effects.
- `stop!` in `audio.cljs` sends `stop` to the worklet (`stop_all`).
- Offline: `output-for-track` returns `ac.destination`, and the TEST1 harness renders via
  `play-event` on a fresh `OfflineAudioContext`.

## Implementation

### 1. Core controls

`packages/core/src/repulse/params.cljs`: `room`, `size`, `delay`, `delay-time`,
`delay-feedback`, `orbit`, the same two-arity shape as TL7a. Register them in
`packages/lisp/src/repulse/lisp/builtins/params.cljs`. Test them in `params_test.cljs`.

### 2. Orbit buses (`app/src/repulse/orbits.cljs`, new)

```clojure
(def n-orbits 4)

(defn orbit-bus
  "Lazily create (and cache per AudioContext, in a WeakMap) the bus for orbit i:
   {:room-in GainNode :delay-in GainNode :conv ConvolverNode :delay DelayNode
    :fb GainNode :out GainNode}. room-in → conv → out; delay-in → delay ⇄ fb, delay → out.
   out connects to master-gain (live) or ac.destination (offline)."
  [ac i] …)

(defn apply-orbit-settings!
  "Set size / delay-time / delay-feedback on orbit i at time t when present in the event."
  [ac i t value] …)

(defn reset-orbits! [ac] …)  ; defaults; called from audio/stop!
```

- `DelayNode` with `maxDelayTime` 4. Feedback and time use `setValueAtTime` at `t`.
- Impulse responses: cache per (context, size rounded to 0.05) so at most 21 buffers per
  context. Generate with the same noise-burst formula as `reverb.js` (move
  `makeImpulseResponse` into a shared CLJS fn; `reverb.js` may keep its own copy because
  plugins are standalone JS). Use a fixed PRNG seed per size step instead of
  `Math.random()`, so offline renders are reproducible. Swapping `conv.buffer` when the
  size changes may click on a running tail. That's acceptable; document it.
- Orbit outputs are created on first use, so an orbit nobody sends to costs nothing.

### 3. JS path sends (`audio.cljs`)

Extend `with-inserts` (rename to `event-output` if clearer): when `:room` or `:delay`
is > 0, insert an `event-out` GainNode at the end of the chain that connects to `dest`
(dry) **and** to `room-in`/`delay-in` of the event's orbit through two per-event send
GainNodes (levels `room`, `delay`). Call `apply-orbit-settings!` for every event that has
orbit setting keys, including events with sends at 0. Cleanup timer as in TL7a.

### 4. WASM path sends

- Append slots to the `trigger_v3` layout: `12 room · 13 delay · 14 orbit`.
  `ActiveVoice` gains `room: f32, delay: f32, orbit: u8`.
- `AudioEngine` gains a **pre-allocated** bus buffer:
  `bus: Vec<f32>` of `128 · 2 · (1 + 2·N_ORBITS)` floats, allocated in `new`, resized only
  if `n_samples > 128` (never on the audio thread in practice: render quanta are 128).
  Layout: `[bus][frame][channel]`, bus 0 = dry, 1..=4 = room sends orbit 0–3, 5..=8 =
  delay sends orbit 0–3.
- `process_block_raw` keeps returning the dry interleaved buffer (existing tests
  unchanged). New `process_block_buses_raw(n, t) -> &[f32]` fills `self.bus`. The panned
  voice sample is added to bus 0, and also to the room/delay bus of its orbit, scaled
  by `room`/`delay`, when those are > 0. The engine's amp/pan transitions apply to
  bus 0 only.
- wasm-bindgen export `process_block_buses(n, t) -> Float32Array` (one copy into JS per
  block, like today).
- `worklet.js`: construct with `numberOfOutputs: 9, outputChannelCount: [2 ×9]`, and in
  `process()` de-interleave each bus into `outputs[k]`.
- `init-worklet!`: connect output 0 → `@master-gain`, outputs 1–4 → orbit i `room-in`,
  outputs 5–8 → orbit i `delay-in`, via `(.connect node dest output-index)`. Orbit buses
  for the live context are created eagerly here (needed for the connections).
- WASM orbit *settings* (`size`, `delay-time`, `delay-feedback`) are applied on the
  main thread by `apply-orbit-settings!` in `play-event`, whichever path plays the voice.
- `npm run build:wasm`.

## Definition of done

- [ ] Offline: `(->> (seq :c4 :_ :_ :_) (room 0))` vs `(room 0.8)`: RMS of the last quarter-cycle (after the note's decay) is ≥ 20 dB higher with `room 0.8`; the first 50 ms (dry onset) differ by < 1 dB.
- [ ] Offline: `(size 0.1)` vs `(size 1)` with `room 0.8`: tail RMS 1.5 s after the onset is ≥ 10 dB higher for `size 1`.
- [ ] Offline: `(->> (seq :sd :_ :_ :_) (delay 0.5) (delay-time 0.25) (delay-feedback 0.5))` at 1 cycle = 2 s: `countOnsets` finds the hit plus ≥ 3 echoes at 0.25 s spacing (±10 ms), each quieter than the last.
- [ ] Offline: `(delay 0)` produces exactly one onset (no echo), and the orbit nodes are not created.
- [ ] Orbits are independent: `(stack (->> (seq :bd) (room 0.8) (size 0.1) (orbit 0)) (->> (late 1/2 (seq :bd)) (room 0.8) (size 1) (orbit 1)))` has a longer tail after the second hit than after the first, by ≥ 10 dB at +1 s.
- [ ] `(orbit 7 pat)` plays on orbit 3 and prints the exact warning `orbit 7 is out of range 0–3; using 3` once per evaluation.
- [ ] Rust: a voice with `room 0.5, orbit 2` writes non-zero samples only to bus 0 and bus 3 (room orbit 2); with `room 0` the send buses stay exactly 0.0.
- [ ] Rust: `process_block_raw` output for a voice is unchanged by this phase (bit-identical dry bus), and the bus buffer is not reallocated across 1000 consecutive 128-frame blocks (pointer equality).
- [ ] Live (Playwright on the real app, or a manual protocol step if the CI browser can't run the worklet): an `(synth :epiano)` pattern with `(room 0.6)` produces a reverb tail. This proves the worklet send outputs are wired.
- [ ] Patterned/signal sends: `(room (seq 0 0.8) (seq :c4 :c4))` gives a tail only after the second note.
- [ ] `(stop)` then play again: orbit settings are back to defaults (`delay-time` 0.25).
- [ ] Rule 3 for all 6 names; USAGE.md "Sends & orbits"; parity rows updated; ROADMAP delivered entry.
- [ ] `npm run test:all` and `npx shadow-cljs compile app` pass.
- [ ] Human listen recorded in the PR: reverb send on/off, delay echoes, two orbits with different sizes.
- [ ] The PR description ends with a `## Test protocol` section (CLAUDE.md Rule 5).

## What NOT to do

- No reverb or delay DSP in Rust: the send effects exist only as Web Audio nodes.
- No `delay-sync`, `roomlp`/`roomdim`/`roomfade`, custom impulse responses, ducking: **TL7c** or later.
- No change to `track-fx` / global `fx` routing, and orbits are not user-loadable plugins.
- No offline worklet (EXP1); offline sends use the JS path.
- No more than 4 orbits, no per-orbit effect chains beyond reverb + delay.
